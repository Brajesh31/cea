# 🏛️ Project Governance

## Project scope
The repository is a small educational collection of three independent Streamlit scripts. It is not a supported production ML platform.

## Decision making
Changes should be proposed through issues or pull requests. Maintainers review scope, algorithm correctness, safety, test evidence and documentation quality before merging.

## Technical decisions
Significant changes to algorithm definitions, data collection, persistent state, dependencies or deployment should be recorded using an architecture decision record template.

## Release authority
The repository maintainer approves releases and determines whether the documented behavior and limitations are accurate.

## Community behavior
Contributors and maintainers follow the repository Code of Conduct. Security vulnerabilities should be reported through the private channel described by SECURITY.md.
